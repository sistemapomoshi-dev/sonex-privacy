# Политика конфиденциальности приложения SONEX

Версия: 1.0  
Дата вступления в силу: 24 октября 2026 г.

## 1. Общие положения

1.1. Настоящая Политика конфиденциальности (далее — «Политика») описывает порядок обработки, хранения, передачи и удаления информации при использовании мобильного приложения SONEX для операционной системы Android (далее — «Приложение»).

1.2. SONEX — музыкальный проигрыватель, предназначенный для воспроизведения локальных аудиофайлов, управления музыкальной библиотекой, подключения внешних источников музыки и использования дополнительных функций воспроизведения.

1.3. Разработчиком Приложения является физическое лицо:  
Разработчик: Бушихин Андрей Анатольевич  
Электронная почта для обращений: andrey_bushihin@mail.ru

1.4. Разработчик стремится минимизировать обработку пользовательской информации, обеспечивать преимущественно локальное хранение данных и предоставлять пользователю контроль над подключением внешних сервисов.

1.5. Настоящая Политика применяется к работе Приложения, а также к обработке персональных данных непосредственно разработчиком в случаях, когда такая обработка осуществляется.

1.6. Вопросы обработки персональных данных регулируются применимыми положениями законодательства Российской Федерации, включая Федеральный закон от 27 июля 2006 года № 152-ФЗ «О персональных данных».

## 2. Основные принципы конфиденциальности

2.1. SONEX предназначен для использования без обязательной регистрации в системе разработчика.

2.2. Приложение не использует собственный сервер разработчика для централизованного хранения музыкальной библиотеки, плейлистов, истории прослушивания, паролей и токенов пользователей.

2.3. Приложение не содержит встроенной рекламы и систем аналитики пользовательского поведения.

2.4. При обычном использовании Приложения разработчик не получает автоматически:

- музыкальные файлы пользователя;
- содержимое локальной музыкальной библиотеки;
- пользовательские плейлисты;
- историю прослушивания;
- пароли и токены подключённых сервисов;
- содержимое файлов, находящихся на пользовательских серверах.

2.5. Основная информация, необходимая для работы Приложения, хранится непосредственно на устройстве пользователя.

2.6. При использовании сетевых функций информация может передаваться сторонним сервисам или серверам, подключённым пользователем.

2.7. Отсутствие собственного сервера разработчика не означает полного отсутствия сетевых запросов. Некоторые функции SONEX требуют обмена данными с внешними системами.

## 3. Какие данные использует Приложение

### 3.1. Локальные музыкальные файлы

Для воспроизведения и организации музыкальной библиотеки SONEX может получать доступ к:

- аудиофайлам, доступным на устройстве;
- названиям композиций;
- именам исполнителей;
- названиям альбомов;
- обложкам альбомов;
- длительности и другим метаданным аудиофайлов;
- расположению файлов в доступном хранилище.

Эти сведения используются для поиска, сортировки, отображения и воспроизведения музыки.

Обработка локальной музыкальной библиотеки осуществляется на устройстве пользователя. Разработчик не получает её содержимое автоматически.

### 3.2. Плейлисты и настройки

Приложение может сохранять:

- пользовательские плейлисты;
- избранные композиции;
- настройки интерфейса;
- параметры воспроизведения;
- выбранные источники музыки;
- настройки подключённых интеграций.

Указанная информация используется для сохранения пользовательских предпочтений и корректной работы функций SONEX.

### 3.3. История прослушивания

Приложение может сохранять локальную историю воспроизведения, включая сведения о прослушанных композициях, исполнителях и времени прослушивания.

Эти данные используются для отображения истории и работы связанных с ней функций.

История прослушивания не передаётся разработчику автоматически.

При использовании функций синхронизации или скробблинга сведения о прослушивании могут передаваться соответствующему стороннему сервису.

### 3.4. Данные подключённых источников

Если пользователь подключает внешний музыкальный источник, SONEX может использовать:

- адрес сервера;
- имя пользователя;
- пароль;
- токен доступа;
- идентификатор учётной записи;
- сведения о доступных папках и библиотеках;
- параметры подключения.

Эта информация необходима для авторизации, получения списка файлов, воспроизведения музыки и выполнения других выбранных пользователем операций.

### 3.5. Данные, передаваемые при обращении к разработчику

Если пользователь самостоятельно обращается к разработчику по электронной почте, разработчик может получать:

- адрес электронной почты отправителя;
- имя, если оно указано;
- текст обращения;
- предоставленные вложения;
- сведения, необходимые для рассмотрения обращения.

Эта информация используется для ответа пользователю, технической поддержки и рассмотрения запросов, связанных с конфиденциальностью.

## 4. Цели использования информации

SONEX использует информацию для следующих целей:

- воспроизведение локальных и удалённых аудиофайлов;
- отображение и организация музыкальной библиотеки;
- создание и использование плейлистов;
- сохранение настроек пользователя;
- подключение облачных хранилищ и медиасерверов;
- авторизация в выбранных сервисах;
- загрузка музыки для офлайн-прослушивания;
- отображение истории прослушивания;
- получение текстов песен;
- передача сведений о прослушивании в подключённые сервисы;
- воспроизведение музыки на совместимых внешних устройствах;
- рассмотрение обращений пользователей.

Приложение не использует пользовательскую информацию для рекламного профилирования.

В случаях, когда разработчик непосредственно обрабатывает персональные данные, такая обработка осуществляется при наличии предусмотренного законодательством Российской Федерации правового основания.

Предоставление системного разрешения Android само по себе не заменяет отдельного согласия на обработку персональных данных, если такое согласие необходимо по закону.

## 5. Подключение сторонних сервисов

SONEX поддерживает взаимодействие с внешними сервисами и пользовательскими серверами.

Передаваемая информация зависит от конкретного сервиса и используемой функции.

### 5.1. Яндекс Диск

При подключении Яндекс Диска SONEX использует предоставленный токен доступа для обращения к файлам и папкам, доступным пользователю.

Для работы интеграции могут передаваться запросы на получение списка файлов, метаданных и содержимого выбранных аудиофайлов.

Пользователь может загружать музыку на устройство для офлайн-воспроизведения.

Обработка информации на стороне Яндекс Диска регулируется правилами соответствующего сервиса.

### 5.2. Plex

При авторизации в Plex учётные данные пользователя могут передаваться сервису Plex для выполнения входа.

В предусмотренном интеграцией сценарии адрес электронной почты и пароль передаются для авторизации, после чего для дальнейших обращений используется полученный токен доступа.

SONEX может направлять запросы к подключённой библиотеке Plex и передавать сведения, необходимые для работы функций медиасервера.

### 5.3. Jellyfin и Subsonic

При подключении Jellyfin или Subsonic SONEX использует адрес сервера и необходимые данные авторизации.

Приложение может запрашивать сведения о музыкальной библиотеке, получать аудиофайлы и обмениваться информацией, необходимой для воспроизведения.

Если пользователь использует функции учёта воспроизведений, соответствующие сведения могут передаваться подключённому серверу.

### 5.4. SMB и WebDAV

При подключении сетевых хранилищ по протоколам SMB или WebDAV SONEX использует предоставленные пользователем параметры соединения и, при необходимости, учётные данные.

Обмен информацией осуществляется с выбранным сервером.

Безопасность передачи зависит от используемого протокола, настроек сервера и защищённости сетевого соединения.

### 5.5. ListenBrainz

При подключении ListenBrainz SONEX использует токен доступа пользователя.

При включённой функции передачи сведений о прослушивании сервису могут направляться:

- названия композиций;
- имена исполнителей;
- сведения об альбомах;
- временные отметки прослушивания;
- другие данные, необходимые для соответствующей функции.

Отключение интеграции прекращает дальнейшую передачу данных через неё, но не удаляет автоматически сведения, ранее полученные сервисом ListenBrainz.

### 5.6. LRCLIB

При использовании функции поиска текстов песен SONEX может обращаться к сервису LRCLIB.

Для поиска могут передаваться название композиции, имя исполнителя и другие музыкальные метаданные, необходимые для определения соответствующего текста.

Сервис также может получать техническую информацию о сетевом запросе.

### 5.7. Google Cast и Chromecast

При использовании функции трансляции SONEX взаимодействует с совместимыми устройствами воспроизведения.

Для обеспечения трансляции могут передаваться сведения о композиции, адрес аудиоресурса и команды управления воспроизведением.

В зависимости от способа подключения могут использоваться компоненты технологии Google Cast.

### 5.8. Самостоятельная обработка данных сторонними сервисами

Владельцы подключённых сервисов могут самостоятельно определять порядок обработки информации, которую они получают.

Перед использованием внешнего сервиса пользователю рекомендуется ознакомиться с его политикой конфиденциальности.

Разработчик SONEX не управляет хранением и удалением данных в независимых сторонних сервисах.

## 6. Техническая информация и сетевые соединения

6.1. При обращении к внешним серверам получатель запроса может получать технические сведения, включая:

- IP-адрес соединения;
- дату и время запроса;
- сетевые заголовки;
- сведения, необходимые для выполнения запроса.

6.2. Такие данные могут обрабатываться соответствующим сервером в соответствии с его настройками и правилами.

6.3. Передача технических сведений внешнему сервису не означает их автоматической передачи разработчику SONEX.

6.4. Приложение не использует собственную систему отслеживания действий пользователей в рекламных или аналитических целях.

## 7. Разрешения Android

Для выполнения отдельных функций SONEX может запрашивать разрешения операционной системы Android.

**Доступ к аудиофайлам.** Необходим для обнаружения, отображения и воспроизведения музыки, доступной на устройстве.

**Уведомления.** Используются для отображения состояния воспроизведения, элементов управления музыкой и информации о выполняемых операциях.

**Доступ к хранилищу на старых версиях Android.** Может использоваться для работы с музыкальными файлами, их сохранения и изменения метаданных в пределах возможностей соответствующей версии Android.

**Сетевые возможности.** Используются для подключения внешних музыкальных источников, загрузки файлов, получения текстов песен и работы сетевых функций.

Пользователь может управлять системными разрешениями через настройки Android.

Отказ в предоставлении разрешения может ограничить только те функции, для которых оно необходимо.

## 8. Хранение и защита информации

8.1. Основные пользовательские данные SONEX хранятся локально на устройстве.

8.2. Для защиты сохраняемых учётных данных и токенов Приложение использует механизмы шифрования с применением Android Keystore.

8.3. Доступ к внутренним данным Приложения ограничивается средствами операционной системы Android.

8.4. Разработчик не имеет постоянного удалённого доступа к локальным данным Приложения на устройстве пользователя.

8.5. При подключении к серверам по незащищённым протоколам (например, HTTP или SMB без шифрования) данные могут передаваться по сети без шифрования. Пользователю рекомендуется по возможности использовать защищённые соединения.

## 9. Сроки хранения

9.1. Данные на устройстве хранятся до тех пор, пока пользователь ими пользуется:

- данные входа в Яндекс Диск, выбранные папки и загруженные для офлайн-прослушивания файлы — до выхода из аккаунта Яндекс Диска в Приложении;
- параметры и учётные данные серверов — до удаления сервера в разделе «Источники»;
- токен ListenBrainz — до отключения интеграции в настройках Приложения;
- плейлисты, избранное, история прослушивания и настройки — до удаления Приложения или очистки его данных средствами Android.

9.2. Обращения, полученные по электронной почте, разработчик хранит в течение времени, необходимого для их рассмотрения, но не более одного года после завершения переписки, если более длительный срок не требуется по закону.

## 10. Удаление данных

10.1. Пользователь может самостоятельно удалить данные в Приложении:

- выйти из аккаунта Яндекс Диска, удалить сервер или ссылку — в разделе «Источники»;
- отключить ListenBrainz — в настройках Приложения;
- удалить плейлисты, избранное и закладки — в соответствующих разделах Приложения.

10.2. Чтобы удалить все данные Приложения сразу, пользователь может удалить Приложение или очистить его данные в настройках Android.

10.3. Данные, которые пользователь сам передал в подключённые сервисы (Яндекс Диск, Plex, Jellyfin, Subsonic, ListenBrainz и другие), удаляются в соответствии с правилами этих сервисов.

10.4. По запросу на адрес электронной почты, указанный в пункте 1.3, разработчик удаляет переписку с пользователем и сведения, полученные в ходе обращения.

## 11. Права пользователя

11.1. Пользователь вправе получить сведения об обработке своих персональных данных разработчиком, потребовать их уточнения или удаления, а также отозвать согласие на их обработку, если обработка основана на согласии.

11.2. Для этого достаточно направить обращение на адрес электронной почты, указанный в пункте 1.3. Разработчик рассматривает обращение и отвечает в сроки, установленные Федеральным законом № 152-ФЗ.

## 12. Дети

12.1. Приложение не предназначено специально для детей и не собирает сознательно персональные данные детей.

12.2. Если законный представитель ребёнка считает, что ребёнок передал разработчику персональные данные, он может обратиться по адресу, указанному в пункте 1.3, для их удаления.

## 13. Изменения Политики

13.1. Разработчик может изменять настоящую Политику. Новая редакция публикуется по той же ссылке с указанием новой версии и даты вступления в силу.

13.2. Продолжение использования Приложения после публикации новой редакции означает ознакомление пользователя с ней.
